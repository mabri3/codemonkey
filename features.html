codemonkey

A scriptable coding-agent CLI (Python 3.11, uv, Typer, httpx) for OpenAI-style and Anthropic-style endpoints, defaulting to the local llama.cpp server (http://192.168.50.113:8080/v1, Qwen3.8-27B-NVFP4-MTP-VERY-HIGH.gguf). Non-interactive exec mode for CI/other agents; interactive rich REPL when run bare.

Completed features

  • Repo scaffold + layered config (defaults → user YAML → project YAML → .env → env vars → CLI; secrets masked; strategy/enum validation)CYCLE 1
  • Provider layer: OpenAI-compatible + Anthropic Messages API, raw httpx, SSE streaming, auth-header handling, models commandCYCLE 2
  • Tools (read/write/edit_file/list_dir/glob/search/shell/update_plan/web_fetch) + sandbox policy (read-only / workspace-write / danger-full-access, `--add-dir` roots)CYCLE 3
  • Tool protocol: prompt protocol (TOOL_CALL: parser, fence/garbage tolerant) + native extraction (OpenAI tools, Anthropic tool_use, streaming incl. input_json_delta)CYCLE 4
  • Agent loop: model → tool calls → sandbox-gated execution → result feedback, max_turns bail, per-turn eventsCYCLE 4
  • tool_protocol: auto catches the llama.cpp tools-parameter HTTP 500 and retries the same turn with the prompt protocol, remembering the fallback per provider (A9 mechanic)CYCLE 4

How to run

uv run codemonkey --version
uv run codemonkey config          # effective merged config (secrets masked)
uv run codemonkey models          # list models from the active provider
uv run pytest -q                  # unit suite (73 tests, no network)

Known limitations

  • exec / review / sessions / REPL commands are not wired yet (cycles 5–9).
  • Structured output (--output-schema), session persistence, and pluggable strategies land in cycles 6–7.
  • Live-LLM probes require the local llama.cpp server to be up.
